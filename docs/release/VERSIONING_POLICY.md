# LifeCircle OS — Versioning Policy

**Status**: Approved
**Owner**: Engineering Lead
**Effective**: Phase 4 Sprint 4

## 1. Semantic Versioning

All public releases follow **[Semantic Versioning 2.0.0](https://semver.org/)** (`MAJOR.MINOR.PATCH`):

| Increment | When |
| :--- | :--- |
| **MAJOR** | Breaking changes to the Public SDK contract |
| **MINOR** | Backwards-compatible new capabilities or new bounded contexts |
| **PATCH** | Bug fixes, security patches, performance improvements |

## 2. Release Train

| Channel | Tag Pattern | Audience | Criteria |
| :--- | :--- | :--- | :--- |
| `development` | Auto-built on `develop` branch | Internal engineers | Must pass Gate 1–4 |
| `beta` | `v1.2.3-beta.N` | Internal testers & partners | Must pass all 5 CI gates |
| `rc` | `v1.2.3-rc.N` | Release candidate | Passes full CI + security scan |
| `stable` | `v1.2.3` | General availability | Approved by Release Manager |

## 3. Git Tag Conventions

```
v{MAJOR}.{MINOR}.{PATCH}            # Stable: v1.0.0
v{MAJOR}.{MINOR}.{PATCH}-beta.{N}   # Beta:   v1.0.0-beta.1
v{MAJOR}.{MINOR}.{PATCH}-rc.{N}     # RC:     v1.0.0-rc.1
```

Tags MUST be created on the `release/{version}` branch, never directly on `main`.

## 4. SDK Compatibility Policy

- The Public SDK contract (`lib/src/sdk/v1/`) is considered stable after v1.0.0.
- Breaking SDK changes increment MAJOR and require a new SDK version directory (`sdk/v2/`).
- The previous SDK version is maintained for a minimum of **2 MINOR releases** after deprecation.
- SDK version compatibility is declared in `pubspec.yaml`.

## 5. ADR Version Tracking

Every ADR carries a version number in its filename (e.g., `ADR-007`). When an ADR is superseded, it is archived with `status: Superseded` and a reference to the new ADR. ADR numbers never recycle.

## 6. Changelog Automation

Changelogs are auto-generated by GitHub Actions from conventional commit messages:
- `feat:` → Added
- `fix:` → Fixed
- `perf:` → Performance
- `sec:` → Security
- `break:` → Breaking Changes (triggers MAJOR bump prompt)
- `docs:` → Documentation
- `refactor:` → Internal
