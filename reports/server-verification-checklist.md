# Server Verification Checklist

**Status:** Proposed (SEC-004C.3)

Backend engineers MUST verify every item on this checklist during the implementation of the Remote Trust Verification endpoints.

## Phase 1: Attestation Validation
- [ ] **Nonce Validation**: The `nonce` embedded in the Attestation Object MUST strictly match the exact nonce generated by the server for that specific device/user.
- [ ] **Timestamp Validation**: The `nonce` MUST have been issued within the last 5 minutes.
- [ ] **Replay Cache**: The `nonce` MUST be deleted from the cache immediately upon first use (successful or failed).
- [ ] **Certificate Chain Validation**: The x509 certificate chain MUST root back to the official Apple Root CA or Google Hardware Attestation Root CA.
- [ ] **App Integrity**: The `appId` / `bundleId` extracted from the certificate MUST exactly match `com.lifecircle.mobile`.
- [ ] **Hardware-Backed Validation**: The attestation extension MUST verify that the key was generated inside a TEE (Trusted Execution Environment) or Secure Enclave.
- [ ] **Fraud Signals**: For Play Integrity, the `deviceRecognitionVerdict` MUST be parsed to ensure the device is not an emulator or rooted.

## Phase 2: Registration
- [ ] **Key Registration**: Extract the public key and hardware counter from the validated Attestation Object.
- [ ] **Database Binding**: Persist the Public Key strongly bound to the `deviceId` and `userId`.
- [ ] **Key Revocation**: Automatically revoke any previous Attestation Keys for that `deviceId`.

## Phase 3: Assertion Verification
- [ ] **Payload Hash**: Calculate the SHA-256 hash of the received HTTP request body.
- [ ] **Signature Verification**: Verify the ECDSA signature against the registered Public Key using the payload hash.
- [ ] **Counter Validation**: Verify that the hardware counter provided in the assertion is strictly greater than the last known counter in the database. Update the database counter.
- [ ] **Audit Logging**: Log the `deviceId`, `counter`, and `timestamp` for all successful assertions to provide a cryptographically provable audit trail.
